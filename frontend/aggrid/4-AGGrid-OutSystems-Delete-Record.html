    Delete a customer after a confirmation

    Each row gets a Delete button. A click opens a confirmation dialog. Yes calls the REST API, removes the customer and refreshes the grid; No closes the dialog. AGGridCore is not changed: the button, the click and the dialog belong to CustomerPortal. CustomerPortal's script also becomes generic, so later buttons need only a JSON column, a CSS rule and a handler.

    Part 0

    How it works

    ≈ 5 min

    0.1The flow

    The confirmation is an OutSystems Popup with Yes and No, built like the Add dialog in document 3. The script only reports which row's button was clicked.

    0.2About the test API

    JSONPlaceholder answers a delete with 200 but doesn't remove anything. So the screen removes the row from RowsJson itself (RemoveRow), and a page reload shows all customers again. With an API that stores data, use Refresh Data instead (step 3.6).

    Part 1

    Script, CSS and local test

    ≈ 10 min

    On your PC, in C:\AGGrid\customerportal-scripts from document 2.

    1.1Make customerportal-grid.js generic

    Replace the whole file with this version, once. The row click works as before. Any column with a colId and the cell class cp-btn is now a button: a click calls the function with the same colId under buttons. Later buttons need no change to this file (step 4.2).

    New in this versionWhat it does
    buttons in attach()One function per button column, keyed by its colId. A click, or Enter, on such a cell calls it with the row's id and its cells.
    cp-btnMarks a cell as a button: on every row with cellClass, or only on some rows with cellClassRules (step 4.2). In a button column, a cell without it does nothing. A cp-btn cell without a function only logs a warning; it never counts as a row click.
    rowCellsThe row's visible texts by colId, for example cells.name for the dialog. Only cells on screen are included; for other data, use the id.
    No browser confirm()The question is asked by CustomerPortal's own dialog (step 3.5).

    1.2Create customerportal-grid.css

    In the same folder. Button columns are empty in the data. This CSS gives every cp-btn cell the same button look, and one short rule per button sets its label. It keeps the hand cursor from document 2. You paste it into OutSystems in step 3.2.

    The Customers screen

    ≈ 20 min

    3.1Update the script in OutSystems

    1. Interface tab → Scripts → double-click customerportalgrid.
    2. Select all of its text, replace it with the file from step 1.1, and close the editor.

    The Customers screen already requires the script (document 2, step 2.1).

    3.2Update the Style Sheet

    Open the Customers screen's Style Sheet. Replace the hand-cursor line from document 2 with all of customerportal-grid.css (step 1.2).

    3.3Add the Delete column

    Open CustomersOnInitialize and replace the code of the BuildConfig node. Only the last column is new:

    Setting on the Delete columnWhy
    colId: "delete"The column has no data field. A click on its cells calls buttons["delete"] (step 3.7).
    cellClass: ["cp-btn", "cp-delete"]cp-btn makes the cells a button for the script and the CSS; cp-delete gives it the label Delete.
    pinned: "right"The button stays visible when the grid scrolls sideways.
    sortable, filter, resizable, suppress…No sorting, filter, menu or side-bar entry for a button column.
    export: falseKeeps the column out of the CSV and Excel files. This is a setting of the core, not of AG Grid.

    3.4Add the variables

    Local variableData TypeDefaultHolds
    DeleteIdInteger—The customer to delete
    DeleteNameText—Its name, for the question
    ShowDeleteDialogBooleanFalseWhether the confirmation is open

    3.5The confirmation dialog

    1. Drag a Popup onto the screen, below the Add dialog. Set Show Popup = ShowDeleteDialog.
    2. Inside it, add a Text Delete customer as the title.
    3. Below it, add an Expression: "Delete " + DeleteName + "? This cannot be undone."
    4. Add two Buttons:
      • Yes, delete: On Click → New Client Action ConfirmDeleteOnClick (step 3.6).
      • No: On Click → New Client Action CancelDeleteOnClick, with an Assign: ShowDeleteDialog = False.

    3.6The client actions

    AskDelete is called by the script. Right-click the Customers screen → Add Client Action, name it AskDelete, and add two inputs in this order: CustomerId (Integer), then CustomerName (Text).

    ConfirmDeleteOnClick runs when the user clicks Yes, delete:

    JavaScript node RemoveRow: inputs RowsJson (Text) = RowsJson and CustomerId (Integer) = DeleteId; output NewRowsJson (Text).

    With an API that stores data

    Replace RemoveRow and the RowsJson assignment with Refresh Data → GetCustomersJson, as in document 3, step 2.5.

    3.7On Ready: connect the Delete button

    Open CustomersOnReady and replace the code of the AttachCustomerGrid node. Only the buttons part is new; AreaId stays CustomerGridArea.Id.

    Names and order

    The key "delete" must be the column's colId (3.3). $actions.AskDelete(…) passes its values in the order of the action's inputs: CustomerId, then CustomerName (3.6). The name after $actions. must match exactly.

    3.8Publish and verify

    1. TrueChange: no red errors. 1-Click Publish → Open in Browser.
    Expected

    • Delete on a row opens the dialog with that customer's name. No closes it, and nothing changes.
    • Yes, delete closes the dialog and shows Customer deleted. The row disappears, and the status bar counts one row less.
    • A customer added with document 3 can be deleted the same way.
    • A click elsewhere in a row still logs A row was clicked.

    A button on some rows only

    To show a button only where the data allows it, for example an Edit button for rows whose is_editable field is true, use cellClassRules instead of cellClass. The rule is text, so it fits in JSON; data is the row:

    Rows where the rule is false show no button, and a click there does nothing. The CSS rule for the label (.cp-edit::after { content: "Edit"; }) and the handler under buttons are added as above.
