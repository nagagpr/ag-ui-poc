    Add a customer through a dialog

    An Add customer button above the grid opens a dialog. Save sends the new customer to the REST API, closes the dialog, and the grid shows the new row. AGGridCore and CustomerPortal's script are not changed.

    • Builds on documents 1 and 2
    • AGGridCore unchanged
    • Only CustomerPortal changes
    • ≈ 45 min
    Status
    • Verified: the JavaScript nodes BuildNewCustomer and AppendRow were run against the live API and the document 1 core. POST /users answered 201 with id 11, and the grid showed the new customer, "Rows: 11". A second customer got id 12.
    • Service Studio: the steps were not clicked through; menu names can differ slightly between versions.
    Part 0

    How it works

    ≈ 5 min

    0.1The flow

    The grid redraws by itself: the block's On Parameters Changed (document 1, step 2.9) runs whenever RowsJson changes.

    0.2About the test API

    JSONPlaceholder answers a create with 201 and a new id (11), but it doesn't store the customer. Reading the list again would therefore not show it. So the screen adds the new row to RowsJson itself (AppendRow).

    • After a page reload, the original 10 customers are shown again. This is expected with the test API.
    • With an API that stores data, use Refresh Data instead of AppendRow (step 2.5).

    0.3What changes where

    ModuleChange
    AGGridCoreNone.
    CustomerPortalA REST method CreateUser, a server action CustomerCreate, five variables, a button, a dialog with a form, and three client actions. customerportal-grid.js is not changed.
    EmployeeDirectoryNone.

    Part 2

    The dialog on the screen

    ≈ 25 min

    Everything below is on the Customers screen.

    2.1Add the variables

    Local variableData TypeDefaultHolds
    NewName, NewEmail, NewCity, NewCompanyText—What the user types in the dialog
    ShowAddDialogBooleanFalseWhether the dialog is open

    2.2The Add customer button

    1. Drag a Button from the toolbox onto the screen, above CustomerGridArea. Set its text to Add customer.
    2. On Click → New Client Action, named AddCustomerOnClick, with an Assign: ShowAddDialog = True.

    2.3The dialog with the form

    1. Drag a Popup from the toolbox onto the screen, below the button. Set Show Popup = ShowAddDialog. The dialog opens when the variable is True and closes when it is False.
    2. Inside the Popup, add a Text Add customer as the title.
    3. Below it, drag a Form and name it AddForm.
    4. Inside the Form, add four Input widgets. Set each one's Variable and Prompt as in the tree below. On the first Input, set Mandatory = Yes.
    5. Add two Buttons inside the Form:
      • Save: On Click → New Client Action SaveCustomerOnClick (step 2.4).
      • Cancel: set Built-in Validations = No, then On Click → New Client Action CancelAddOnClick, with an Assign: ShowAddDialog = False.
    Why Built-in Validations = No on Cancel

    Otherwise clicking Cancel with an empty Name first marks the field as required. Cancel should just close the dialog.

    2.4Save: call the API and refresh the grid

    Build SaveCustomerOnClick like this:

    Each node's values are shown in the flow. Set them in the node's Properties, after closing its editor for JavaScript nodes.

    JavaScript node BuildNewCustomer: inputs Name, Email, City, Company (Text); output BodyJson (Text).

    JavaScript node AppendRow: inputs RowsJson, BodyJson, ResponseJson (Text); output NewRowsJson (Text).

    Field names

    The body uses the API's field names (name, email, address.city, company.name), which are also the grid's column fields. That is why the new row fills every column.

    2.5With an API that stores data

    Skip this step for the test API. With a real API that stores the new customer, read the list again instead of adding the row yourself:

    Refresh Data runs GetCustomersJson again; its On After Fetch (document 1, step 4.5) puts the fresh list in RowsJson, and the grid redraws. AppendRow is then not needed.

    • Cancel closes the dialog without changes.
