    Shared AG Grid Enterprise component for OutSystems

    This guide sets up AG Grid Enterprise as one public OutSystems Web Block and uses it in two consumer applications: CustomerPortal shows customers from a REST API, and EmployeeDirectory groups employees by department. Follow the parts in order; each part ends with a check. Documents 2–4 then add a row click, Add and Delete to CustomerPortal, one feature at a time.

    0.4Licence key

    SituationBehaviour
    No key (until purchase)All features work. AG Grid shows a watermark and a License Key Not Found notice in the browser console. On localhost the watermark is not shown.
    Key built inNo watermark and no notice
    • The key is added at build time through .env.local (steps 1.6 and 6.4). It is never entered in OutSystems, and the consumer applications are not affected.
    • Production use requires the licence. Confirm that it covers every application and developer that uses the block.
    • The key is visible in the browser by design. Keep .env.local out of version control.
    • A key covers AG Grid versions released before its end date. Check this before upgrading AG Grid.

    0.5How it works

    The block reacts to three of its own lifecycle events:

    Block eventWhen OutSystems runs itWhat we do
    On ReadyOnce, when the block's HTML exists on the pageAGGridCore.mount(…): create the grid
    On Parameters ChangedEvery time the screen gives the block a new input value (for example new rows)AGGridCore.update(…): refresh the same grid
    On DestroyWhen the block leaves the page (the user goes to another screen)AGGridCore.destroy(…): free memory
    Note

    The grid is created in On Ready, not On Initialize, because the container exists only once the block is rendered.

    0.6Design principle

    AGGridCore is shared, so it contains only generic behaviour: columns and rows from JSON, the switchable features, the selection event and exports. Behaviour that one application needs, such as Add, Delete or a row click, is added by that application, without changing the core. Documents 2–4 do this for CustomerPortal:

    The core providesAn application can
    ConfigJson columns passed to AG Grid as they are (cellClass, pinned, cellClassRules…)Add its own columns, such as a Delete column, and colour cells by value
    Row ids (rowIdField) and column ids in the grid's HTMLHandle clicks on rows and buttons with its own script
    A container around the block, styled by the applicationDraw buttons and a pointer cursor with its own CSS
    The OnSelectionChanged eventAct on the selected rows
    "export": false on a columnKeep its own columns out of CSV and Excel

    The core changes only for generic needs: fixes, AG Grid upgrades, the licence key, or new switches every application can use. Section 7.4 lists the limits.

    0.7Key terms

    Producer / consumer
    A producer module makes elements public; a consumer module uses them through Manage Dependencies.
    Web Block
    A reusable part of a screen with inputs and events. AGGridCoreBlock holds the grid.
    Required Scripts
    Scripts a block or screen loads automatically when it is shown.
    Client action / JavaScript node
    Browser-side logic. A JavaScript node reads its inputs with $parameters and calls client actions with $actions.
    Aggregate / JSON Serialize
    A database query, and the step that turns its result into JSON text.
    TrueChange / 1-Click Publish
    The errors and warnings panel, and the button that compiles and deploys (F5).
    Column definition / field
    AG Grid's description of a column; field is the value to show, with dots for nested values (Customer.Name).
    Row id
    A unique value per row (rowIdField). It keeps the selection on refresh and identifies the row for application scripts.

    Part 6

    Maintenance and licence

    ≈ 15 min each time

    The library is changed in one place. These steps keep the consumer applications working.

    Safe changes ✓

    New optional JSON keys with defaults · new block inputs that are not mandatory and have a default value · bug fixes inside main.js · a new licence key · upgrading AG Grid after testing with test.html.

    Breaking changes ✗

    Renaming or removing a block input or event parameter · making an input mandatory · changing what an existing JSON key means · removing a JSON key that apps use.

    6.1Change, rebuild, retest

    1. Make your change:
      • Code change: edit src/main.js and raise the version, for example const VERSION = "1.0.1";
      • New licence key (for example after a renewal): replace the key in .env.local.
      • New AG Grid version: first check that your key covers it (step 0.4). Then install both packages with the same new version, for example npm install ag-grid-community@36.3.0 ag-grid-enterprise@36.3.0 --save-exact.
    2. Run npm run build.
    3. Open test.html again (step 1.9) and check that everything still works. With a key, the console shows no licence notice.

    6.2Replace the script in the producer

    1. In AGGridCore, Interface → Scripts: select aggridcore and use the option to replace its file with the new dist\ag-grid-core.js.
    2. If your Service Studio version has no replace option: delete the script, import the new file (step 2.2), and add it again to the block's Required Scripts.
    3. 1-Click Publish, then test GridDemo first.

    6.3Refresh the consumers

    1. Open CustomerPortal. Service Studio shows that a dependency is outdated.
    2. Open Manage Dependencies (Ctrl+Q), refresh AGGridCore, click Apply, and publish.
    3. Do the same for EmployeeDirectory.
    4. In the browser, press Ctrl+F5 once to skip the old cached file, then check AGGridCore.version and AGGridCore.hasLicenseKey in the console.
    In bigger environments

    LifeTime's impact analysis shows which apps depend on AGGridCore before you deploy it to test or production. Deploy the producer together with its consumers.

    6.4When the licence key arrives

    1. In aggrid-core, create .env.local with your key, as in step 1.6.
    2. Optional: raise the version in src/main.js, for example to "1.0.1", so that you can see the new file is in use.
    3. Run npm run build. Open test.html (step 1.9): it says licence key built in: yes, and the console has no red licence box.
    4. Replace the script in AGGridCore (6.2) and publish.
    5. Refresh the consumers (6.3). Their screens, scripts and JSON don't change.
    6. In each app, press Ctrl+F5: no watermark, and AGGridCore.hasLicenseKey is true.
    "Invalid License Key" instead?

    The key is incomplete or has extra characters. Paste the whole key on one line, with no quotes and no spaces around =, then rebuild.

    7.3Library API (window.AGGridCore)

    CallPurpose
    mount(containerId, configJson, rowsJson, { height, onSelectionChanged })Create a grid. Called again on the same container, it acts like update.

    Each grid also fires a browser event, aggrid:selectionChanged, on its container. You only need it outside OutSystems.

    The right-click menu offers copy and paste only. Exporting always goes through the block's buttons, so "export": false always applies.
