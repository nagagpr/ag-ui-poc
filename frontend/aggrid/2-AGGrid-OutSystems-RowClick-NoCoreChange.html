    Row click in CustomerPortal, without changing AGGridCore

    CustomerPortal from document 1 gets its own small script. A click on a customer row runs onRowClicked: function (id) { console.log("A row was clicked", id); }. AGGridCore is not opened, rebuilt or published.

    • Builds on document 1
    • AGGridCore unchanged
    • Only CustomerPortal changes
    • ≈ 30 min
    Status
    • Verified: CustomerPortal's script and test page were run against the document 1 core (AGGridCore 1.0.0, AG Grid Enterprise 36.2.0, no licence key) with document 1's column configuration and the live API. A click on Clementine Bauch logs A row was clicked 3, and the Enter key works too. A checkbox only ticks the row. Clicks on headers, the side bar, the status bar and the paging bar log nothing.
    • Service Studio: the steps were not clicked through; menu names can differ slightly between versions.
    Part 0

    How it works

    ≈ 5 min

    0.1AG Grid's gridOptions and this setup

    In AG Grid's documentation, a row click is a function inside the grid options:

    In this setup, AGGridCore creates the grid options itself. Apps pass only JSON text through the block (ConfigJson, RowsJson), and JSON can hold values but not functions:

    In the snippetIn CustomerPortal
    columnDefscolumns in ConfigJson (document 1, step 4.6)
    pagination: trueOn by default (features.pagination)
    getRowHeight: (params) => 25A fixed height is a plain value: gridOptions: { rowHeight: 25 } in ConfigJson (tested)
    onRowClickedA function, so it can't travel as JSON. CustomerPortal's own script provides it (this document).

    The script works from outside the grid. AG Grid writes each row's id on the row in the page (<div class="ag-row" row-id="3">), taken from rowIdField: "id". A click travels up to a container around the block, where the script reads that id:

    Part 1

    CustomerPortal's script

    ≈ 10 min

    On your PC. The script belongs to CustomerPortal; AGGridCore never loads it.

    1.1Create customerportal-grid.js

    Create the folder C:\AGGrid\customerportal-scripts, next to aggrid-core. In it, create customerportal-grid.js:

    PartWhat it does
    attach(areaId, handlers)Adds one click listener and one Enter-key listener to the container around the block. It does not call or change AGGridCore. Calling it again only replaces the handlers.
    findAreaFinds the container by its id. If the id is empty, it uses the container with the Style Class customer-grid-area.
    locateReads the clicked row's id (row-id) and column (col-id). Clicks outside rows (headers, side bar, status bar, paging) are ignored.
    handleIgnores the checkbox column, so ticking a row only selects it. Any other cell calls onRowClicked.
    toIdTurns the text "3" back into the number 3 for OutSystems.

    Part 2

    CustomerPortal in Service Studio

    ≈ 15 min

    Open CustomerPortal only. Everything below is on the Customers screen.

    2.1Import the script

    1. Interface tab → right-click Scripts → Import Script… → choose customerportal-grid.js. It appears as customerportalgrid.
    2. Select the Customers screen. Properties → Required Scripts → add Scripts.customerportalgrid.
    Later changes

    To change the script later, double-click it under Scripts, edit it in Service Studio, and publish CustomerPortal.

    2.2Put a container around the block

    The block on the screen

    Under Interface › UI Flows › AGGridCore, AGGridCoreBlock is the block's definition in the other module; its right-click menu has no Enclose option. Use the copy of the block that sits on the Customers screen.

    1. In the Elements tab, under MainFlow, double-click Customers itself (not one of its variables or actions). The canvas shows the Customers screen.
    2. Open the Widget Tree tab, next to Elements. Select AGGridCoreBlock inside Customers.
    3. Right-click it → Enclose in Container. A new Container wraps the block and is selected.
    4. In the container's Properties, set Name = CustomerGridArea and Style Classes = "customer-grid-area", with the quotes.

    No Enclose in Container in your version? Drag a Container from the toolbox onto the screen, then drag AGGridCoreBlock into it in the Widget Tree. The block keeps its inputs and its OnSelectionChanged handler.

    1. Select the Customers screen. Properties → Events: Event = OnReady, Handler = New Client Action.
    2. Drag a JavaScript node between Start and End and name it AttachCustomerGrid.
    3. In the JavaScript editor, add an input parameter AreaId (Text), then paste:
    1. Close the editor and select the AttachCustomerGrid node in the flow. Its Properties now show AreaId.
    2. The AreaId dropdown suggests only variables, so choose Expression Editor…. In the scope tree, expand Widgets › CustomerGridArea, double-click Id, and click Done. The value is CustomerGridArea.Id. You can also type it straight into the field.
    CustomerGridArea not under Widgets?

    Only widgets with a Name are listed. Check step 2.2. If AreaId stays empty, the script uses the container with the Style Class customer-grid-area instead.

    It doesn't matter whether the grid already has rows when On Ready runs. The listener sits on the container, so rows that appear later, after paging or sorting, are covered too.

    2.5Publish and verify

    1. TrueChange: no red errors. 1-Click Publish → Open in Browser.
    2. Press F12 → Console. Click Clementine Bauch: the console shows A row was clicked 3.
