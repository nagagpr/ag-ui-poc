SAGE on Amazon ECS: IAM Roles to Create

Four roles for deploying and running SAGE 5.0 on Amazon ECS (Express Mode, Fargate) through GitHub Actions

Roles to create

Role namePurposeTrusted by
**1. sage-github-actions-deploy-roleLets the GitHub Actions pipeline push the image to ECR and create/update the ECS service. Used only for deploymentsGitHub Actions (OIDC)
**2. sage-ecs-task-execution-roleLets ECS pull the container image from ECR and write container logs to CloudWatch when a task startsecs-tasks.amazonaws.com
**3. sage-storage-task-roleLets the running application read and write its files in s3://<S3_BUCKET>/sage/ onlyecs-tasks.amazonaws.com
**4. sage-ecs-infrastructure-roleLets ECS Express Mode create and manage the load balancer, HTTPS certificate, target groups, security groups and auto scalingecs.amazonaws.com

Replace the placeholders before applying: <ACCOUNT_ID>, <REGION>, <ECS_CLUSTER>, <ECS_SERVICE>, <ECR_REPOSITORY>, <S3_BUCKET>, <GITHUB_OWNER>, <OWNER_ID>, <GITHUB_REPO>, <REPO_ID>, <GITHUB_ENVIRONMENT>.

Also needed once per account: the GitHub OIDC identity provider (https://token.actions.githubusercontent.com, audience sts.amazonaws.com), and the service-linked roles for ecs.amazonaws.com, elasticloadbalancing.amazonaws.com and ecs.application-autoscaling.amazonaws.com.

1. sage-github-actions-deploy-role

Purpose: deployment only. GitHub Actions gets short-lived credentials through OIDC (no stored AWS keys), pushes the image to ECR, creates/updates the ECS Express Mode service, and passes roles 2–4 to ECS.

Trust policy (Web identity → GitHub OIDC; only the approved repository and environment):

Permissions (inline policy sage-github-actions-deploy-role-policy):

2. sage-ecs-task-execution-role

Purpose: used by ECS while starting a container, to pull the image from ECR and send logs to CloudWatch. The application cannot use this role.

Trust policy (AWS service → Elastic Container Service Task):

Permissions: attach the AWS-managed policy **AmazonECSTaskExecutionRolePolicy**.

3. sage-storage-task-role

Purpose: the application's own AWS identity. It can only read, write and delete files under the sage/ folder of the SAGE bucket.

Trust policy: the same as role 2 (ecs-tasks.amazonaws.com).

Permissions (inline policy sage-storage-task-role-policy):

4. sage-ecs-infrastructure-role

Purpose: used by ECS Express Mode itself to create and manage the load balancer, HTTPS certificate, target groups, security groups and auto scaling for the service.

Trust policy (AWS service → Elastic Container Service):

Permissions: attach the AWS-managed policy **AmazonECSInfrastructureRoleforExpressGatewayServices**.
