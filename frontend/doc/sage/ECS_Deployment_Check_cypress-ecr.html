3.2 Run the AWS CLI checks from your PC

Same checks as CloudShell, but from PowerShell on your PC. You sign in with your company AWS SSO (the same identity you use for the console).

  1. Install AWS CLI v2 for Windows (MSI from the AWS documentation page *Installing the AWS CLI*), then open a new PowerShell and run aws --version.
  2. Run aws configure sso and answer: SSO session name rnt; SSO start URL = your company AWS access portal URL (the page where you pick the DSE.DEV account); SSO region us-east-1; registration scopes: press Enter. A browser opens to approve.
  3. Choose account DSE.DEV (137474890109) and your role. Default region us-east-1, output json, profile name dse-dev.
  4. Next time, sign in with aws sso login --profile dse-dev (sessions expire after some hours).

3.3 Open the private app in your browser without VPN (optional, needs IT)

If the load balancer is internal and your PC has no route to the VPC, you can tunnel through AWS Systems Manager (SSM). This needs a small EC2 instance in vpc-0758ef1be26b0b173 that is managed by SSM (IT usually has one, or creates it). No inbound ports or public IP are needed.

  1. Install the Session Manager plugin for the AWS CLI on your PC (MSI from the AWS documentation page *Install the Session Manager plugin*).
  2. Ask IT for the instance ID of an SSM-managed EC2 instance in the VPC, and for permission ssm:StartSession on it with document AWS-StartPortForwardingSessionToRemoteHost.
  3. Start the tunnel (keep this window open). It listens on your PC's port 443, so the real host name works unchanged. If port 443 is already used on your PC (e.g. IIS or a local web server), stop that first:

In a second PowerShell window, test through the tunnel. --resolve sends the real host name, which the load balancer needs to route to this service:

To use a browser through the tunnel, the host name must point to your PC. This needs local administrator rights:

  • Add the line 127.0.0.1 cy-1c81d1fb1e714e9dbc6f8bbe90a93686.ecs.us-east-1.on.aws to C:\Windows\System32\drivers\etc\hosts (open Notepad as administrator).
  • Then browse to https://cy-1c81d1fb1e714e9dbc6f8bbe90a93686.ecs.us-east-1.on.aws/ (the normal URL, no port) while the tunnel is open. Remove the hosts line when you're done.
Why not just browse to https://localhost?

Express Mode shares one load balancer between services and picks the service by host name. A request for localhost doesn't match any rule, so it fails (404 / certificate error). The --resolve option or the hosts-file line keeps the real host name.
