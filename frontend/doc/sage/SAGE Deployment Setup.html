**1. sage-github-actions-deploy-roleLets the sage5.0 GitHub Actions pipeline push the image to ECR, register a new task-definition revision and update the existing sage5-0 ECS service. Used only for deploymentsGitHub Actions (OIDC), repository sanumolu-rnt-c/sage5.0, environment production

Naming: AWS does not allow . in ECS service, target group or load balancer names, so those use sage5-0. The GitHub repository, ECR repository and log group keep sage5.0. Placeholders still to fill: <ACCOUNT_ID>, <ECS_CLUSTER>, <S3_BUCKET> (DEV: sage-storage-dev).

After this, every push to master in sage5.0 builds the image, pushes sage5.0:<git-sha> to ECR, registers a new task-definition revision and updates the sage5-0 service. Nothing else is created by the pipeline.

1. sage-github-actions-deploy-role

Purpose: deployment only. GitHub Actions gets short-lived credentials through OIDC (no stored AWS keys). It pushes the image to ECR, registers a new task-definition revision and updates the existing sage5-0 service. It cannot create or delete clusters, services, load balancers, security groups or IAM roles.

2. sage-ecs-task-execution-role

Purpose: used by ECS while starting a sage5.0 container, to pull the image from ECR and send logs to CloudWatch. The application cannot use this role. Goes in the task definition as executionRoleArn.

Trust policy (AWS service → Elastic Container Service Task):

Permissions: attach the AWS-managed policy **AmazonECSTaskExecutionRolePolicy**.

3. sage-storage-task-role

Purpose: the sage5.0 application's own AWS identity. It can only read and write files under the sage/ folder of the SAGE bucket. It cannot delete files. Goes in the task definition as taskRoleArn.

Trust policy: the same as role 2 (ecs-tasks.amazonaws.com).
