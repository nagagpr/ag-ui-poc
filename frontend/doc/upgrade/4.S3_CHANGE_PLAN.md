# sage-node — Change Plan 1: S3 artifact storage

> Based on the Copilot analysis of the real sage-node code (file:line references below come from
> that report). Line numbers will drift once edits start — always re-locate by function name.
>
> **Rule:** S3 holds files (PNG, WebM, HTML, JSON reports, XLSX/CSV, traces).
> **Not a data migration:** no backfill of old local files. Only new writes go to S3.
> **Order:** this plan first. Deploy and validate it before starting
> [4.POSTGRES_CHANGE_PLAN.md](4.POSTGRES_CHANGE_PLAN.md).

**Root causes**
1. `artifact-store.ts` writes local first and mirrors to S3 **asynchronously** (`:175`) and reads
   **local first** (`:107`). S3 is a backup copy, not the source of truth.
2. Listings use `fs.readdirSync` (`recorder.tool.ts:355, 380`, `explorer.tool.ts:129`,
   `figma.tool.ts:250`, `ai-driver.tool.ts:205`) → after an ECS restart the UI shows nothing even
   though the objects exist in S3.
3. Download routes use `res.sendFile()` (`recorder.route.ts:146`, `explorer.route.ts:74`).
4. Several modules write files directly (Playwright `path:`, `fs.copyFile`) and never call
   `mirrorLocalFile()` / `writeLocalAndMirror()`.

## Phase 1 — Make S3 the source of truth for files

### 1.1 Refactor `artifact-store.ts` (foundation — do this first)

Add a driver switch and a complete API. Keep `mirrorLocalFile()` / `writeLocalAndMirror()` as thin
wrappers around the new API so existing callers keep working during the change.

```
STORAGE_DRIVER = local | s3     (local Docker → local, ECS → s3; default: s3 if S3_BUCKET_NAME set, else local)
LOCAL_STORAGE_ROOT = /app/data  (local driver root, and temp dir for s3 driver)
```

| Function | Behaviour with `s3` driver |
|---|---|
| `put(key, body \| filePath, contentType)` | **Await** `PutObject` (multipart via `@aws-sdk/lib-storage` `Upload` for files > 5 MB / videos). Throw on failure — no silent async mirror. |
| `putFile(key, localPath, { deleteLocal })` | Upload a file Playwright/Python already wrote, then delete the temp copy. |
| `get(key)` | `GetObject` → Buffer. S3 first; local only when driver = `local`. |
| `getStream(key)` | `GetObject` → Readable stream (for downloads). |
| `list(prefix)` | `ListObjectsV2` with **pagination** (`ContinuationToken`); returns `{ key, size, lastModified }[]`. |
| `exists(key)` | `HeadObject` (404 → false). |
| `delete(key)` / `deletePrefix(prefix)` | `DeleteObject` / list + `DeleteObjects` (batches of 1000). |
| `presign(key, ttlSeconds)` | `@aws-sdk/s3-request-presigner` `getSignedUrl(GetObjectCommand)`, default 900 s. |
| `keyFor(category, ...parts)` | Builds `${S3_BASE_PREFIX}/${category}/${parts.join('/')}`; rejects `..`, absolute paths, backslashes. |

The `local` driver implements the same interface on top of `fs` so local Docker keeps working
unchanged. Content types: `image/png`, `video/webm`, `application/json`, `text/html`,
`text/csv`, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, `application/zip` (traces).

**Key layout** (existing categories + two new ones):

```
sage/recorded-tests/<testId>/steps/<n>.png
sage/recorded-tests/<testId>/metadata.json
sage/test-reports/<executionId>/screenshots/<stepId>-pass|fail|final.png
sage/test-reports/<executionId>/video.webm
sage/test-reports/<executionId>/result.json
sage/explorer-reports/<crawlId>/report.json
sage/explorer-reports/<crawlId>/screenshots/<pageId>.png
sage/figma-reports/<reportId>/report.json
sage/ai-driver-artifacts/<runId>/run.json | screenshots/*.png | videos/*.webm
sage/dms-reports/<reportId>/report.html | report.json          (NEW category)
sage/manual-test-imports/<importId>/<originalFileName>          (NEW category)
```

The IAM policy already allows `sage/*`, so the new categories need no IAM change.

### 1.2 Upload the missing binaries

| # | File | Change |
|---|---|---|
| 1 | `recorder.tool.ts:826, 835, 846` | After each Playwright `page.screenshot({ path })` (pass/fail/final), call `putFile(keyFor('test-reports', executionId, 'screenshots', …), path, { deleteLocal: true })`. Or reuse the `captureScreenshot()` pattern from `:170` (`page.screenshot()` → Buffer → `put`). Save the returned key in the execution result, not the local path. |
| 2 | `recorder.tool.ts` (video) | If `recordVideo` is enabled: after `context.close()`, `await page.video()?.path()` → `putFile(... 'video.webm')`. |
| 3 | `recorder.tool.ts` (stop / saved screenshots) | Wrap the upload in try/catch; on failure log + return an error to the caller (don't report "saved" when S3 failed). |
| 4 | `explorer.tool.ts:383` | Upload each screenshot to `explorer-reports/<crawlId>/screenshots/`; store keys in the report JSON. |
| 5 | `ai-driver.tool.ts:123` | Replace copy-to-run-dir with `putFile` for every PNG/WebM produced by `ai_driver.py`; write keys into `run.json`. |
| 6 | DMS report generator (locate in `src/` or `dms/`) | Upload HTML + JSON to `dms-reports/<reportId>/`. |
| 7 | Manual test import route (XLSX/CSV upload) | Upload the original file to `manual-test-imports/<importId>/` before/after parsing; keep parsing from a temp file or buffer. |
| 8 | Python scripts (`python/ai_driver.py`, `story_readiness_analyzer.py`) | No S3 code in Python. Python keeps writing to a temp dir passed in by Node; Node uploads the results and deletes the temp dir. |

Temp files: use `os.tmpdir()`/`LOCAL_STORAGE_ROOT/tmp/<runId>` and delete them in a `finally` block.

### 1.3 Replace directory listings with `store.list()`

| File | Current | New |
|---|---|---|
| `recorder.tool.ts:355` | `fs.readdirSync` | `store.list(keyFor('recorded-tests'))` → group by `<testId>` → `get(metadata.json)` |
| `recorder.tool.ts:380` | `fs.readdirSync` | same pattern for its folder |
| `explorer.tool.ts:129` | `fs.readdirSync` | `store.list(keyFor('explorer-reports'))`, filter `*/report.json` |
| `figma.tool.ts:250` | `fs.readdirSync` | `store.list(keyFor('figma-reports'))`, filter `*/report.json` |
| `ai-driver.tool.ts:205` | `fs.readdirSync` | `store.list(keyFor('ai-driver-artifacts'))`, filter `*/run.json` |

Sort by `lastModified` desc and cap per page. This is an interim solution: listing S3 + one `GetObject`
per item works at current volume. Phase 2 replaces listings with SQL queries.

Also switch every JSON **read** of these reports (`fs.readFileSync(...json)`) to `store.get()`.

### 1.4 Download routes

| Route | Change |
|---|---|
| `recorder.route.ts:146` | Replace `res.sendFile()` with `store.getStream(key)` piped to `res` (set `Content-Type`, `Content-Length`, `Cache-Control: private`) **or** `302` to `store.presign(key)`. |
| `explorer.route.ts:74` | Same. |
| Any other `res.sendFile`/`res.download`/`express.static` for artifacts | Same. Search the whole repo. |

Security: build the key server-side from validated ids (`keyFor`) — never accept a raw key/path
from the request. Keep the existing auth/identity check on these routes. Return 404 on
`NoSuchKey`.

Recommendation: stream for images shown inline in the UI; presigned URL for large downloads
(videos, reports). No UI change is needed if the route URLs stay the same.

### 1.5 Config, health, packages

- `package.json`: add `@aws-sdk/client-s3`, `@aws-sdk/lib-storage`, `@aws-sdk/s3-request-presigner` (if not already present).
- Config loader: `STORAGE_DRIVER`, `S3_BUCKET_NAME`, `S3_BASE_PREFIX`, `AWS_REGION`, `LOCAL_STORAGE_ROOT`. Fail fast at startup if driver = `s3` and bucket is missing.
- `/api/health`: add `storage: { driver, ok }` (`HeadBucket` or `list` with `MaxKeys=1`). Report status, don't fail the ECS health check on it.
- `deploy-node.yml`: add `{"name":"STORAGE_DRIVER","value":"s3"}` to `environment-variables`.
- `docker-compose` / local run: `STORAGE_DRIVER=local` (optionally MinIO for testing the s3 driver locally).
- Dockerfile: no change.
- Check `ECS_TASK_ROLE_ARN` points to the **application task role** with the S3 policy, not the Express Mode infrastructure role.

### 1.6 Phase 1 validation (on ECS)

1. Run Recorder (record + execute, pass and fail) → screenshots + video in `sage/recorded-tests/` and `sage/test-reports/`.
2. Run Explorer → `report.json` + screenshots in `sage/explorer-reports/<crawlId>/`.
3. Run AI Driver → `run.json`, PNG, WebM in `sage/ai-driver-artifacts/<runId>/`.
4. Generate a DMS report → `sage/dms-reports/`.
5. Upload a manual test XLSX/CSV → `sage/manual-test-imports/`.
6. `aws s3 ls s3://<bucket>/sage/ --recursive` shows all of the above.
7. **Force a new ECS deployment** (restart the task).
8. UI still lists every item and every screenshot/video/report opens/downloads.
9. CloudWatch: no `AccessDenied`, `NoSuchKey`, unhandled upload errors.
10. Local Docker with `STORAGE_DRIVER=local` still works end to end.

**Phase 1 is done only when step 8 passes.**
