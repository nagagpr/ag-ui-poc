## Phase 2 — PostgreSQL for records

### 2.1 Infrastructure (manual, once)

RDS PostgreSQL 16 (`db.t4g.micro`, private, encrypted, 7-day backups) in the ECS service's
VPC/subnets; security group allows 5432 from the ECS service; credentials in Secrets Manager
(`sage-node/<env>/postgres`, JSON `{username,password}`). Execution role needs
`secretsmanager:GetSecretValue` on that secret. Commands are in `2.POSTGRES_MIGRATION.md` §1a.

### 2.2 Application design

- Driver: `pg` + `@types/pg` (unless the repo already uses an ORM — then use that).
- `src/db/pool.ts`: `pg.Pool` (max 10, `ssl: { rejectUnauthorized: true }` with RDS CA bundle or `require`), graceful shutdown on SIGTERM.
- `src/db/migrate.ts`: runs `db/migrations/*.sql` in order at startup inside a transaction with a Postgres advisory lock, recording each in `sage.schema_migrations`.
- One repository module per store (`src/db/repositories/*.repo.ts`) with the **same method signatures the current JSON stores expose**, so call sites barely change.
- Switch: `DATA_STORE_DRIVER = json | postgres` (local Docker may keep `json`, or use a compose Postgres).
- Encryption/HMAC: keep existing app-level logic; store the resulting encrypted value / signature as-is.
- Env vars: `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_SSL`, `DATA_STORE_DRIVER`.

### 2.3 What is stored — tables and format

Common conventions: schema `sage`; ids are `TEXT` in the format the app already generates;
times `TIMESTAMPTZ`; flexible/nested data `JSONB`; every file reference is an `s3_key TEXT`
(never binary content); `created_at`/`updated_at` on every table.

| Area (from analysis) | Table(s) | Key columns | Files referenced (S3) |
|---|---|---|---|
| Recorder metadata & suites | `recorder_suites`, `recorded_tests` | suite_id, name, url, steps `JSONB`, status, created_by | step screenshots, `metadata.json` |
| Execution results | `test_executions`, `test_execution_steps` | execution_id, test_id FK, status, started_at, finished_at, duration_ms, error; per step: index, action, status, message | pass/fail/final screenshots, video |
| Explorer report metadata | `explorer_reports` | crawl_id, start_url, status, page_count, summary `JSONB` | `report.json`, screenshots |
| Figma report metadata | `figma_reports` | report_id, file_key, node_id, status, summary `JSONB` | `report.json` |
| AI Driver runs | `ai_driver_runs` | run_id, story/goal, status, steps `JSONB`, result `JSONB` | `run.json`, PNG, WebM |
| DMS reports | `dms_reports` | report_id, type, status, summary `JSONB` | HTML, JSON |
| Manual test imports | `manual_test_imports` | import_id, file_name, format, row_count, status, errors `JSONB` | original XLSX/CSV |
| Lifecycle packages | `lifecycle_packages`, `lifecycle_events` | package_id, stage, status, data `JSONB`; events: entity_type, entity_id, from/to status | — |
| Test Repository | `test_repository` | test_case_id, title, jira_key, tags `TEXT[]`, source, content `JSONB`, status | linked recordings |
| Quality Graph | `quality_graph_nodes`, `quality_graph_edges` | node: id, node_type, properties `JSONB`; edge: source_id FK, target_id FK, relationship | — |
| Reconciliation | `reconciliation_records` | reference_id, status, details `JSONB`, reconciled_at | — |
| Ask SAGE | `ask_sage_sessions`, `ask_sage_messages` | session: user_identity, title; message: session_id FK, role, content, tokens | — |
| Agentic missions & memory | `agentic_missions`, `agentic_memory` | mission: type, status, input/result `JSONB`; memory: mission_id FK, key, value `JSONB` | mission reports |
| Audit events | `audit_events` (append-only) | entity_type, entity_id, action, actor, payload `JSONB`, hmac_signature | — |
| All files (optional index) | `artifacts` | s3_key PK, category, owner_type, owner_id, content_type, size_bytes | the object itself |

Example (pattern for the others):

```sql
CREATE TABLE sage.test_executions (
    execution_id   TEXT PRIMARY KEY,
    test_id        TEXT NOT NULL REFERENCES sage.recorded_tests(test_id) ON DELETE CASCADE,
    status         TEXT NOT NULL CHECK (status IN ('queued','running','passed','failed','error')),
    started_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    finished_at    TIMESTAMPTZ,
    duration_ms    INTEGER,
    error          TEXT,
    video_s3_key   TEXT,
    result_s3_key  TEXT,
    summary        JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_by     TEXT,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_test_executions_test ON sage.test_executions (test_id, started_at DESC);
```

Audit table: grant the app role `INSERT, SELECT` only (no `UPDATE/DELETE`).

**Final column lists must come from the real TypeScript interfaces** — Copilot generates
`db/migrations/0001_init_schema.sql` and `0002_indexes.sql` from them (prompt P2-A below).

Write order inside a flow: upload file to S3 → insert/update row with `s3_key`. If the insert
fails, delete the uploaded object (or leave it; it's harmless) — never write a row pointing to a
missing key.

### 2.5 Phase 2 validation

1. Migrations applied (`SELECT * FROM sage.schema_migrations`).
2. Exercise each flow once; confirm a row per table and that its `s3_key` exists in S3.
3. Restart ECS task → UI lists everything from Postgres.
4. No local JSON/NDJSON written under `/app/data` (check with `find /app/data -newer ...` via ECS Exec, or logs).
5. Pool stays ≤ 10 connections (`pg_stat_activity`).

After Phase 2 is validated and nothing persistent remains on local disk, `max-task-count` can be
raised in a separate change (also check in-memory state such as running Recorder sessions).
